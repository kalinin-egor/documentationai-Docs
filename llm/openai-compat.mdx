Three wire protocols reach the same models, the same balance and the same
usage log. Pick whichever your tooling already speaks.

| Protocol | Base URL | Auth header |
|----------|----------|-------------|
| OpenAI Chat Completions, Responses, Images, [Embeddings & rerank](/llm/embeddings), Models | `https://api.gpuniq.com/v1/openai` | `Authorization: Bearer gpuniq_...` |
| OpenAI Responses (bare path) | `https://api.gpuniq.com/v1` | `Authorization: Bearer gpuniq_...` |
| Anthropic Messages | `https://api.gpuniq.com` | `x-api-key` or `Authorization: Bearer` |

## OpenAI Chat Completions

Point any OpenAI-compatible tool at GPUniq by setting two environment variables:

```bash
OPENAI_API_KEY=gpuniq_your_key
OPENAI_BASE_URL=https://api.gpuniq.com/v1/openai
```

Every field of the OpenAI Chat Completions protocol is forwarded unchanged: `tools`, `tool_choice`, `response_format`, `logprobs`, `seed`, `stream`, `stream_options`, etc.

Authentication takes either header on every `/v1/openai/*` route (and
`/v1/responses`): `Authorization: Bearer gpuniq_…`, the shape the SDKs send,
or `X-API-Key: gpuniq_…`, the shape the native API uses. A missing
credential is `401 authentication_required` in the OpenAI error envelope.
Successful responses carry the `X-RateLimit-*` headers.

### `usage.cost` is what you were charged

The `usage.cost` field on `chat/completions` reports the dollars GPUniq charged after discounts and cached-input pricing. To read the receipt on a stream, request `stream_options.include_usage: true` and read the last usage chunk before `data: [DONE]`.

With [ruble billing](/changelog#ruble-billing-at-the-rate-you-topped-up-at) enabled, `cost_rub` is the ruble amount recorded for the same operation. GPUniq spends the oldest available top-up first. If one charge uses two top-ups at different rates, `fx_rate_rub` is their weighted rate for that charge. A confirmed zero-ruble charge can have `cost_rub: 0` and no effective rate. Accounts billed in dollars omit both ruble fields.

| Endpoint | Receipt in a successful response |
|---|---|
| `POST /v1/openai/chat/completions` | JSON `usage.cost_rub`, or `usage.cost_rub` in the last usage chunk |
| `POST /v1/responses`, `/v1/openai/responses` | JSON `usage.cost_rub`, or `response.usage.cost_rub` in the `response.completed` event |
| `POST /v1/messages` | JSON `usage.cost_rub`, or `usage.cost_rub` in the `message_delta` event |
| `POST /v1/openai/images/generations` | `usage.cost_rub` alongside `usage.cost_usd` |
| `POST /v1/openai/embeddings`, `/v1/openai/rerank` | `usage.cost_rub` |
| `POST /v1/llm/chat/completions`, `/v1/llm/images/generations` | `data.cost_rub` alongside `data.cost_usd` |
| `GET /v1/llm/{chat,images,videos}/jobs/{id}` | `data.cost_rub` on the completed job |
| [Previously submitted Topaz, audio or music jobs](/llm/long-generations#previously-submitted-media-jobs) | `data.cost_rub` on the completed job |

During a delayed ruble settlement, a successful stream can send SSE comments while it waits. Keep reading through the terminal usage event. A Messages client can read the settled amounts from `event.usage` on `message_delta`.

```json
{"type":"message_delta","delta":{"stop_reason":"end_turn"},"usage":{"input_tokens":31,"cache_read_input_tokens":6,"output_tokens":11,"cost":0.000162,"cost_rub":0.016654,"fx_rate_rub":102.803481}}
```

A dollar-billed stream can finish before a delayed settlement and omit the final cost. `GET /v1/llm/usage/requests/{id}` returns the recorded amounts and `rub_pricing`. The value `"billed"` identifies a ruble receipt. The value `"market"` identifies a market-rate conversion for display.

### Models list

`GET /v1/openai/models` returns the GPUniq catalog and the external
OpenRouter tier in the OpenAI `{"object": "list", "data": [...]}` shape. It
is the list of model ids, not of what `chat/completions` takes: image models
go to `images/generations` and video models use the native video job API.
The catalog's `media_kind` identifies the matching API. `created` is the vendor's release
timestamp where it is known; `1735689600` (2025-01-01) stands for "unknown".
Prices are not part of the OpenAI schema — read
[`GET /v1/llm/models/catalog`](/llm/models) for them.

### Official OpenAI SDK

<CodeGroup>
```python Python
from openai import OpenAI

client = OpenAI(
    api_key="gpuniq_your_key",
    base_url="https://api.gpuniq.com/v1/openai",
)

resp = client.chat.completions.create(
    model="claude-opus-4-7",
    messages=[{"role": "user", "content": "Write a binary search in Rust."}],
)
print(resp.choices[0].message.content)
```

```javascript Node
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: "gpuniq_your_key",
  baseURL: "https://api.gpuniq.com/v1/openai",
});

const resp = await client.chat.completions.create({
  model: "claude-opus-4-7",
  messages: [{ role: "user", content: "Write a binary search in Rust." }],
});
console.log(resp.choices[0].message.content);
```

```bash cURL
curl https://api.gpuniq.com/v1/openai/chat/completions \
  -H "Authorization: Bearer gpuniq_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-opus-4-7",
    "messages": [{"role": "user", "content": "Write a binary search in Rust."}]
  }'
```

### Streaming

Set `stream: true` — GPUniq returns a `text/event-stream` with byte-identical OpenAI SSE framing:

```python
stream = client.chat.completions.create(
    model="gpt-5.2",
    messages=[{"role": "user", "content": "Explain MoE in one paragraph."}],
    stream=True,
)
for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)
```

### When streaming is unavailable

If the gateway cannot find a streaming route, it returns HTTP 503 with
`error.code` set to `no_streaming_upstream` before the stream opens.
The gateway makes zero generation attempts for that request. If your
application accepts a complete JSON answer, it can issue a new request
with `stream: false` and omit `stream_options`. Handle the result as a
regular Chat Completion. The second request is billed if it succeeds.

Limit that retry to the initial HTTP 503 with this exact error code.
A timeout, lost connection, or error event after streaming starts can
occur after the provider has already produced output.

## Images

`POST /v1/openai/images/generations` matches OpenAI's `images.generate`
protocol and accepts any image slug in the catalog. It is a **legacy
surface** kept so OpenAI-SDK code runs unmodified: it holds the connection
open for the whole render and a client that disconnects mid-render is still
charged for an image it never receives.

For anything new use the job API. Full parameter reference, per-model shape
tables and the migration recipe: [Image generation](/llm/images).

## The Responses API

`POST /v1/responses` (and `POST /v1/openai/responses`) implements OpenAI's
Responses protocol against the same catalog, for SDK code written against
`client.responses.create`.

```python Python
from openai import OpenAI

client = OpenAI(
    api_key="gpuniq_your_key",
    base_url="https://api.gpuniq.com/v1",
)

resp = client.responses.create(
    model="gpt-5.5",
    input="Summarise the CAP theorem in three bullets.",
)
print(resp.output_text)
```

## Anthropic Messages

GPUniq exposes a **native Anthropic Messages API** at `POST /v1/messages` —
not a translation layer bolted onto the OpenAI surface. It accepts the
standard Messages body (`model`, `messages`, `system`, `max_tokens`, `tools`,
`stream`) and, with `stream: true`, returns the Anthropic SSE event sequence
(`message_start` → `content_block_*` → `message_delta` → `message_stop`).
Errors come back in the Anthropic error shape, so the official SDK's typed
exceptions work unchanged.

```python Python
import anthropic

client = anthropic.Anthropic(
    api_key="gpuniq_your_key",
    base_url="https://api.gpuniq.com",
)

msg = client.messages.create(
    model="claude-opus-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Write a binary search in Rust."}],
)
print(msg.content[0].text)
```

<Callout kind="info">
  **Reach for this endpoint when the model is a Claude model and the request
  carries `tools`.** `/v1/messages` is Anthropic's own protocol, so tool
  definitions and tool results travel without a translation step in the
  middle — which is where tool round-trips are most likely to lose fidelity.
</Callout>

## Claude Code

[Claude Code](https://docs.claude.com/en/docs/claude-code) talks to GPUniq directly — GPUniq exposes a native Anthropic Messages API at `/v1/messages`, so no LiteLLM (or any other) proxy is required. Point Claude Code's environment variables straight at GPUniq:

```bash
export ANTHROPIC_BASE_URL=https://api.gpuniq.com
export ANTHROPIC_API_KEY=gpuniq_your_key
export ANTHROPIC_MODEL=claude-opus-4-7              # main model
export ANTHROPIC_SMALL_FAST_MODEL=claude-haiku-4-5  # background/small model
claude
```

Use any Claude slug from `/v1/openai/models` for the two model variables. Streaming and tool use work out of the box. All tokens are billed against your GPUniq balance — no separate Anthropic account required.

<Callout kind="info">
Set `ANTHROPIC_SMALL_FAST_MODEL` too: Claude Code calls a smaller "background" model for things like commit messages and titles. If it points at a slug GPUniq doesn't serve, those background calls fail even when the main model works.
</Callout>

**Settings → Models → Override OpenAI Base URL**:

```
Base URL:  https://api.gpuniq.com/v1/openai
API Key:   gpuniq_your_key
Model:     claude-opus-4-7   # or any slug from /v1/openai/models
```

## Continue.dev / Aider / LiteLLM

Any tool that accepts an `OPENAI_BASE_URL` works the same way:

```bash
export OPENAI_API_KEY=gpuniq_your_key
export OPENAI_BASE_URL=https://api.gpuniq.com/v1/openai

aider --model claude-sonnet-4-6
```

<Callout kind="info">
  The OpenAI-compat endpoint returns raw OpenAI response objects (not wrapped in GPUniq's `ResponseSchema`). Errors use OpenAI's `{"error": {"message", "type", "code"}}` envelope so SDK retry logic works unchanged.
</Callout>
